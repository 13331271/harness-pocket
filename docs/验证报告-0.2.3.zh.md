# Harness Pocket 0.2.3 · 会话发布 EACCES 修复

构建时间：2026-11-20（Asia/Shanghai）

## 报错与根因

实际报错：

```
EACCES: permission denied, link
  '/data/user/0/app.harness.pocket/files/dsh-home/sessions/.../session.v4.jsonl.zstd.8f9b9260bcdc.tmp'
  -> '.../session-f79383eb-.../session.v4.jsonl.zstd'
```

写入方在 `@deepseek-ai/dsh-session-persistence-jsonl` 的 `materializePosix()`：
先写临时文件并 fsync，再用 **硬链接** `link(tmp, finalPath)` 发布，以保证「不覆盖已有会话日志」。

**Android 的 SELinux 在应用私有目录里拒绝 `link(2)`**（`app_data_file` 缺少 `link` 权限，返回 `EACCES`），
所以只要创建会话的第一次快照就失败。这不是我们的派生补丁引入的语义错误，而是这个原语在 Android 上不可用。

同一文件里还有第二处同样用法 `publishCurrentExclusive()`（迁移时发布 current 代际），也会踩同一个坑。

## 修法

保留 `link()` 作为首选（它仍是最强的 no-clobber 原语），在这几类 errno 上回退：
`EACCES / EPERM / EXDEV / ENOSYS / EOPNOTSUPP` → 改为「先 stat 目标确认不存在，再原子 `rename`」。

- `EEXIST`（无论来自 link 还是回退前的检查）**照旧报冲突**，绝不覆盖已有日志；
- 其他真正 IO 错误（如 `EIO`）原样抛出，不吞掉。

补丁文本在 `build-scripts/patch_jsonl_link_android.py`，由 `derive_android_runtime.py` 在派生前应用，
并校验补丁确实落进产出的运行包（缺 `publishNoClobber` 直接让派生失败）。

## 验证

本机 Node 语义测试 `optimization-overlay/link-fallback/publish_noclobber.test.mjs`：**6 / 6 通过**

1. 正常路径走 link，不触发 rename；
2. `EACCES` 回退到原子 rename；
3. `EPERM / EXDEV / ENOSYS / EOPNOTSUPP` 同样回退；
4. 回退路径下目标已存在 → 抛 `EEXIST` 且**不** rename（不覆盖）；
5. link 返回 `EEXIST` → 直接当冲突，不 rename；
6. `EIO` 原样抛出。

另有：Kotlin/JUnit 152 / 152、静态核查 errors 0 / warnings 0 / 受限组件 0 / 16KB `static_compatible`、签名 v2+v3、`zipalign -c -P 16` 通过、身份门禁 clean。
